# OpenRAM SRAM Generation & RISC-V Cache Verification

## Overview

This project is a hands-on exploration of **OpenRAM**, an open-source memory compiler, in the context of a **RISC-V core's memory hierarchy**. The goal is to generate a small SRAM macro using OpenRAM, inspect its outputs, verify its functionality, and understand how such a macro would be used by a cache controller.

The project deliberately separates two concerns:

1. **SRAM generation** – handled by OpenRAM.
2. **Cache controller logic** – a separate RTL design that *uses* the generated SRAM.

This README explains the context, scope, project flow, setup steps, and verification strategy.

---

## Context

Modern RISC-V cores rely on caches to bridge the speed gap between the CPU and main memory. These caches are built from **SRAM arrays** – fast, on-chip memories that store data and tags.

OpenRAM is a tool that automatically generates these SRAM arrays. It produces:

- GDSII layout
- SPICE netlist
- Liberty timing/power models
- Verilog behavioral models
- DRC/LVS verification reports

However, OpenRAM **does not** generate or verify the cache controller itself. The cache controller is a digital logic block (usually written in Verilog/VHDL) that decides what to store, when to evict, and how to handle hits/misses. It sits *around* the SRAM.

In software, the **stack** and **heap** are regions of main memory. When a RISC-V core accesses them, the cache controller may cache that data. The SRAM generated by OpenRAM could be used as the cache's data array or tag array.

This project builds a minimal understanding of that full picture.

## Scope

### In Scope
- Setting up OpenRAM in a Docker environment.
- Creating a minimal SRAM configuration file.
- Running OpenRAM to generate an SRAM macro.
- Inspecting GDS, SPICE, Liberty, and Verilog outputs.
- Running OpenRAM's built-in unit tests.
- Simulating the generated SRAM with a simple SPICE testbench.
- Designing or obtaining a basic cache controller RTL and simulating it with the generated SRAM model.

### Out of Scope
- Full RISC-V SoC integration.
- Advanced cache coherency protocols (MESI, MOESI).
- Commercial PDKs (e.g., TSMC, GlobalFoundries).
- Fabrication and silicon bring-up.
- Formal verification of the cache controller.
